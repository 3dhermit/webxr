# webxr-anatomy — project brief

## What this is
A **classroom teaching tool** for anatomy/physiology subject matter, running in WebXR on
Meta Quest 2. The learner is a **student**, not a developer. Nothing in the product teaches
how the app was built.

Audience of the artefact: school students. Audience of this repo's tooling: the teacher/
builder (that's the teacher, not the class).

## Hard design consequences
- **No developer surface in student mode.** No HUD, no FPS/draw-call counters, no sliders
  labelled "factor". A minimal in-world start screen only. Debug tooling lives in
  `tools/` and behind a query flag (`?debug=1`), never in the default flow.
- **Every interaction must serve a learning outcome**, not an interaction demo. The verbs
  (explode, isolate, cross-section, name, reassemble) exist because each one targets a
  specific understanding of structure and relationship.
- **Correct terminology, age-appropriate register.** Use the real terms (ventricle, valve,
  atrium) — curricula require them — but define them in plain language on first use, and
  keep sentences short for reading while wearing a headset in a noisy room.
- **Assessment is part of the product**, not an extra: retrieval practice (name the part),
  self-explanation prompts while manipulating, and an end-of-lesson check the teacher can
  read.
- **Session length fits a class period.** Design each lesson as a self-contained ~7-minute
  station, plus an optional longer guided sequence.

## Constraints
- Target device: **Quest 2** (90 Hz, <100 draw calls, <750k tris/frame, 4 GB RAM, touch
  controllers only, no depth sensing, grayscale passthrough, DOM overlay unsupported in
  `immersive-vr` — so **all UI is in-world geometry**).
- Lesson payload budget: **< 20 MB** (measured heart lesson: 656 KB).
- Assets: Human Reference Atlas / HuBMAP, CC BY 4.0 — attribution ships in
  `src/assets/anatomy/NOTICE.md`. Never load the whole-body atlas (7.19M tris).

## Architecture stance
- Anatomy is **data**: `src/assets/anatomy/parts.json` (identity, label, system, explode
  axis/spread, fact, quiz) plus a lesson script. Adding a body region = new GLB + generated
  registry, no new code path.
- Pedagogical content is also **data**: objectives, vocabulary, misconceptions, prompts and
  assessment items belong in the lesson JSON, editable by a teacher without touching JS.

## Deployment reality (answered 2026-11-04)
- **Up to 28 headsets in one class section** → effectively 1:1. Therefore: zero-typing boot,
  no accounts, no teacher-led onboarding per student, full state reset on every load, and a
  "ready for the next student" end screen. Self-paced, ~12 min core.
- **Formative feedback only — no stored records.** No backend, no PII, nothing leaves the
  headset after the assets load. Feedback is instant and in-world for the student.
- Consequence to confirm later: how the URL reaches 28 devices (MDM kiosk push such as Meta
  Quest for Business / ManageXR / ArborXR, vs. bookmark, vs. a LAN server). The app is
  designed so any of the three works.
